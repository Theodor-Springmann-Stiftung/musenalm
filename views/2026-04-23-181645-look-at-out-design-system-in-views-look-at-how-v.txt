     Plan: Introduce Fomantic UI — Place Create/Edit Form Pilot

     Context

     The admin edit forms currently use a bespoke CSS class system
     (inputwrapper, inputlabelrow, inputlabel, inputinput) defined in
     views/transform/form.css, with inline IIFE scripts for delete dialogs. The
     goal is to introduce Fomantic UI (full package: CSS + jQuery-based JS) as a
      gradual replacement, starting with the place create/edit form
     (views/routes/admin/ort/edit/body.gohtml) as a self-contained pilot.

     ---
     Step 1 — Install dependencies

     cd views/
     npm install jquery fomantic-ui

     fomantic-ui includes both CSS (dist/components/*.min.css) and jQuery
     plugins (dist/components/*.js). We use the full package, not
     fomantic-ui-css, because the user wants the JS components.

     ---
     Step 2 — Wire jQuery + Fomantic into views/transform/main.js

     jQuery must be global before Fomantic JS files load (they detect
     window.jQuery or use CommonJS require('jquery')).

     Add at the very top of main.js (before all other imports):

     import $ from 'jquery';
     window.$ = $;
     window.jQuery = $;

     // Fomantic UI JS — only what the pilot uses
     import 'fomantic-ui/dist/components/transition';
     import 'fomantic-ui/dist/components/dimmer';
     import 'fomantic-ui/dist/components/modal';
     import 'fomantic-ui/dist/components/checkbox';
     import 'fomantic-ui/dist/components/form';

     // Fomantic UI CSS — individual components only (no site.min.css reset)
     import 'fomantic-ui/dist/components/transition.min.css';
     import 'fomantic-ui/dist/components/dimmer.min.css';
     import 'fomantic-ui/dist/components/modal.min.css';
     import 'fomantic-ui/dist/components/checkbox.min.css';
     import 'fomantic-ui/dist/components/form.min.css';

     Add a initFomantic(root) helper and call it in the existing htmx:afterSwap
     handler that already reinitializes web components:

     function initFomantic(root = document) {
         $(root).find('.ui.checkbox').checkbox();
         // Modals and forms are initialized on demand or by the page script
     }

     Add initFomantic() call alongside the existing post-swap init logic.

     ---
     Step 3 — Update the place form template

     File: views/routes/admin/ort/edit/body.gohtml

     What stays unchanged

     - <edit-page> outer wrapper
     - <duplicate-warning-checker>
     - _simple_entity_edit_header template
     - _simple_entity_action_bar template
     - _status_edit (side column)
     - _simple_entity_related_items
     - simple-entity-form-grid / simple-entity-main-column /
     simple-entity-side-column layout
     - <lookup-field> web component (duplicate detection, too complex to replace
      now)
     - <tool-tip> web component
     - _annotation_field (Trix editor)

     Form field changes — wrap in <div class="ui form">

     Replace each inputwrapper/inputlabelrow/inputlabel/inputinput group with
     Fomantic's .field pattern:

     Before:
     <div class="inputwrapper">
       <div class="inputlabelrow">
         <label for="uri" class="inputlabel">URL</label>
       </div>
       <input name="uri" id="uri" class="inputinput" value="{{ $place.URI }}" />
     </div>

     After:
     <div class="field">
       <label for="uri">URL</label>
       <input name="uri" id="uri" value="{{ $place.URI }}" />
     </div>

     Fields to convert: Name (lookup-field wrapper stays, just change outer
     div), Pseudonyms (textarea), URL (text input).

     Checkbox — Fomantic .ui.checkbox

     Before:
     <div class="inputwrapper shrink-0">
       <div class="px-3 py-2 flex flex-row gap-2 font-bold">
         <input type="checkbox" name="fictional" id="fictional" {{ if 
     $place.Fictional }}checked{{ end }} data-boolean-checkbox />
         <label class="flex items-center gap-1 text-gray-700" 
     for="fictional">Fiktional ...</label>
       </div>
     </div>

     After:
     <div class="ui checkbox shrink-0">
       <input type="checkbox" name="fictional" id="fictional" {{ if 
     $place.Fictional }}checked{{ end }} />
       <label for="fictional">Fiktional ...</label>
     </div>

     Keep the <tool-tip> inside the label.

     Delete dialogs — replace <dialog> + IIFE scripts with Fomantic modals

     All three dialogs (edit-delete-dialog, baende-delete-dialog,
     content-delete-dialog) are replaced with .ui.modal divs. Fomantic modal
     callbacks (onShow, onApprove, onDeny) replace the IIFE event delegation +
     manual dialog.showModal() pattern.

     Basic structure (place delete modal):
     <div class="ui small modal" id="delete-ort-modal">
       <div class="header">Ort löschen?</div>
       <div class="content">
         <p>{{ $place.Name }}</p>
         <p>Der Ort wird gelöscht und aus allen verknüpften Bänden entfernt.</p>
         <!-- related entries list -->
       </div>
       <div class="actions">
         <button class="ui cancel button">Abbrechen</button>
         <button class="ui red approve button">Löschen</button>
       </div>
     </div>

     Trigger (inside action bar area — or can be a data attribute on the delete 
     button):
     Fomantic's .modal('setting', 'onApprove', fn) handles the async fetch +
     POST. The three IIFE scripts collapse to a single <script> block
     initializing all three modals with their respective callbacks.

     For the async baende-delete-dialog (needs to fetch info before confirming):
      use onShow callback to fetch and populate content.

     ---
     Step 4 — CSS conflict mitigation

     Fomantic's component CSS files set some base properties (font-family,
     line-height) on .ui elements. Add overrides after the Fomantic import in
     form.css or at the end of site.css:

     /* After Fomantic UI imports */
     .ui.form, .ui.form input, .ui.form textarea {
       font-family: var(--font-sans);
     }

     Do not import fomantic-ui/dist/components/site.min.css — that's the global
     reset which conflicts with Tailwind.
